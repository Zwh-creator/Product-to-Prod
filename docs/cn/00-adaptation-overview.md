# 00 · 差异化改造总览

返回：[README](../../README.cn-adaptation.md) · [证据账本](01-evidence-base.md) · [作品集方案](06-portfolio-plan.md)

## 1. 为什么改造这个仓库

上游仓库的核心价值不是「会写 PRD」，而是三件产品在评审里最容易被蒙混过关的事：数字没有出处、闸门由想通过的人自己放行、交接时说不清当天已知与未知。它用六种证据标签、机械 lint、以及永远默认 `approved: false` 的设计闸门把这三件事变成可检查的纪律。这一点与国内 AI 产品运营/落地岗位的招聘重心高度重合：岗位要求已经从「懂 AI 概念」转向「能把概率型系统做成可评估、可运营、可交接的生产系统」。[FOUND: https://www.pm.sh.cn/2026%E5%B9%B4%EF%BC%8Cai%E4%BA%A7%E5%93%81%E7%BB%8F%E7%90%86%E6%8B%9B%E8%81%98%E8%A6%80%E6%B1%82%E6%9C%89%E4%BD%95%E5%8F%98%E5%8C%96%EF%BC%9F/] [L5: pm.sh.cn, 2026-11 检索]

但上游是语境中立的：它明确不硬编码任何公司，pack 默认 `none`，也不提供国内合规与国内用人方常见的验收语言。作品集里直接放原仓库，展示的是「我会用一个工具」；放这套改造，展示的是「我知道国内 AI 产品落地卡在哪里，并且能把证据变成需求、优先级、发布与验收」。

## 2. 改造原则：换语境，不换引擎

上游的 pack 机制规定得很清楚：pack 换语境，永远不换流程、不换标签、不增减闸门。[FOUND: https://github.com/naderelewa/Product-to-Prod/blob/main/packs/README.md] [L5: 上游 packs/README.md, 2026-11-25 读取]

因此本次改造严格保持：

1. **六种标签不扩展**，FOUND 必须有锚点，HYPOTHESIS 交付时剥离；
2. **需求循环五阶段 + 三道人闸**不压缩，PRD 仍以 `spec.md / plan.md / data-model.md / contracts/ / slices.json / case-contract.md / design-gate.json` 落盘；
3. **RICE 双镜头不平均**，产品镜头与战略镜头的分歧单独暴露；
4. **GTM 只做配置提案**，不花钱、不发内容、不碰标签容器；
5. **发布验收只读且预声明**，UNVERIFIED 是一等结论，验收权归人。

新增的只有语境层：国内证据账本、国内合规门禁、国内渠道与人设划分、以及面向求职评审的叙事层。

## 3. 五个差异化点

| # | 差异化 | 上游状态 | 本改造增加 | 对应岗位能力信号 |
|---|---|---|---|---|
| D1 | 证据账本本土化 | 框架要求每个主张有标签和来源，但来源由运行者提供 | 15 行国内公开证据，覆盖政策、市场、企业案例、招聘要求；每行有链接、日期、L 级 | 市场洞察 + 不编数字 |
| D2 | 业务落差被量化 | 不预设行业结论 | 46% 规模化应用 vs 9% 显著回报，37 个百分点落差作为问题定义 | 从现象到问题的抽象能力 |
| D3 | 合规成为产品能力 | 通用「不可支持主张清单」 | 显式/隐式标识、备案材料、转人工与关键事项人工确认、日志留存，全部写成需求与验收场景 | 国内落地硬约束 |
| D4 | 评估先于发布 | 验收动词存在，但需运行者预声明 | Eval 门禁作为 P0 需求，准确率/幻觉率/转人工率/P95 延迟/单次成本均设阈值与查询 | Eval-First、模型效果评估 |
| D5 | 求职叙事层 | 无 | 作品集对比表、三步讲述脚本、面试问答、分步落地清单 | 让评审 3 分钟看懂差异 |

## 4. 案例产品：CN-AI-Ops Console

为让方法可评审，改造引入一个具体产品对象：面向国内企业 AI 团队的**AI 产品运营与落地控制台**。

- 服务对象：要同时管客服、办公助手、营销内容等多类 AI 场景的产品/运营团队；
- 核心问题：模型能跑，但效果说不清、上线没门禁、合规材料事后补、反馈回不到下一版；
- 北极星指标：**每周通过业务校验的 AI 任务数（VTC/W）**，而非原始调用量；
- 领先指标：**首周任务完成率**（任务完成且无需人工返工的比例）。

选择这个对象的原因：它把「产品运营」而不是「模型训练」放在中心，正好对应国内岗位里增长最快、也最难包装的「行业流程与 AI 运营」方向。[FOUND: https://www.pm.sh.cn/2026%E5%B9%B4%EF%BC%8Cai%E4%BA%A7%E5%93%81%E7%BB%8F%E7%90%86%E6%8B%9B%E8%81%98%E8%A6%80%E6%B1%82%E6%9C%89%E4%BD%95%E5%8F%98%E5%8C%96%EF%BC%9F/] [L5: pm.sh.cn, 2026-11 检索]

## 6. 诚实的边界

- 本案例没有真实部署，也没有真实埋点数据；所有产品指标均为目标或待确认项，不会被写成 PASS；
- 行业数字来自公开二手报道的部分已标注「转引」，需要原始报告复核的已登记为待确认；
- 上游自陈的弱点依然成立：无 SaaS UI、单人使用、无云看板、只在一个 harness 中验证过。[FOUND: https://github.com/naderelewa/Product-to-Prod#honest-comparison] [L5: 上游 README, 2026-11-25 读取] 本改造不掩盖这些弱点，而是把它们写进作品集的「局限与下一步」。
