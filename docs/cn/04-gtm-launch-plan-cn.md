## 3 · 战役架构（按渠道 × 人设）

**核心姿态**：不卖「更强的模型」，卖「上线前能说清依据、上线后能复核结果」。这是由 37 个百分点的规模化—回报落差推导的定位。[INFERRED: E05；计算见 01-evidence-base.md]

- **内容/公众号** → 人设：AI 产品负责人。主张：Eval-First 的落地方式。创意简报指向：一张「发布前门禁清单」图 + 一段证据账本截图。前置闸门：G-品牌-宣称。
- **行业社群** → 人设：AI 运营/实施顾问。主张：Bad Case 如何变成回归用例。创意简报指向：一个可复用的回流流程图。前置闸门：G-评测-门禁。
- **合作伙伴** → 人设：企业数字化负责人。主张：合规材料前置而不是事后补。创意简报指向：备案与标识材料清单。前置闸门：G-合规-备案。
- **私域试点** → 人设：客服主管。主张：转人工不拦、关键事项人工确认。创意简报指向：SC-05/SC-06 的场景演示。前置闸门：G-客服-转人工。

每条渠道文案都必须先过不可支持主张清单；红闸门的渠道只写准备动作，不写效果承诺。

## 8 · Gate 2 / Gate 3 与复盘占位

- Gate 2 审核：计划 + 战役架构 + 两组配置行；每条闸门引语必须与快照逐字一致。
- Gate 3 审核：跨文档一致性、HYPOTHESIS 剥离、开放项由业主裁决 `inference-confirmed.json`；业主结论只能是 ADOPT / ADOPT-WITH-EDITS / PARK。
- `retro.md` 在 Gate 3 之后写；本案例尚未真实运行，因此复盘文件只记录一条带日期的「未运行，无真实复盘」说明，不伪造经验。
